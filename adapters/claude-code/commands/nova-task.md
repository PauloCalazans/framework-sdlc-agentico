description: Inicia a execução de uma task aprovada no Gate 1 (RED → GREEN → revisão → PR).
---
Task: $ARGUMENTS

Trilha enxuta: o /mudanca já criou a branch, o worktree, o commit docs(mudanca): e, se houver contrato executável, o chore: — pule os passos 1 e 2 e continue no worktree existente.

1. Trilha padrão: confira que o commit `docs(spec): <nome> aprovada (Gate 1)` (ou `… aprovada (Gate 1 delegado, D<n>)`) existe, na branch da task ou já integrado na principal (`git log --grep` na branch/principal), e que spec e design estão com `**Status:** aprovado` nele; `**Status:**` só na árvore de trabalho não basta. Se o documento tem `**Trilha:** enxuta`, confira em vez disso que o commit `docs(mudanca):` existe na branch (registro do Gate 1). Se não, pare e diga o que falta.
2. Leia o `**Branch:**` da task e crie o worktree dentro do repositório: `git worktree add agentic/.estado/worktrees/<nome> -b <branch>`, com `<nome>` = branch com `/` trocado por `-`. Branch empilhada (modo automático, task anterior da mesma spec ainda não integrada): crie a partir da branch anterior (`git worktree add agentic/.estado/worktrees/<nome> -b <branch> <branch anterior>`) e acrescente `**Base:** <branch anterior>` à task (`agentic/processo/ciclo.md`, "Branches empilhadas").
3. Marque a task `**Status:** em-andamento` e crie `agentic/.estado/execucao/<AAAA-MM-DD>-<nome>/progress.md` com a task, o SHA base e o próximo passo.
4. Conduza as fases 3 a 6 de `agentic/processo/ciclo.md` como orquestrador: despache `testes`, depois `dev`, depois `revisor` (modo `diff`), sempre com caminhos absolutos do worktree no brief, incluindo o contrato e o perfil do papel (`agentic/processo/papeis/<papel>.md` e `agentic/projeto/papeis/<papel>.md`). Registre brief e relatório no diretório de execução. Toda decisão sua não prevista na spec, no design ou na task é uma Ruling na seção `## Rulings` da task, commitada na branch (`agentic/processo/ciclo.md`, "Rulings").
5. Se `AGENTS.md` declara que não há plataforma de PR (`Plataforma de PR: nenhuma`): não faça push nem PR — rebase a branch na principal e avise o humano para integrar com `git merge --ff-only <branch>`. Caso contrário: se `agentic/auto-mode` contém `enabled: true`, publique o PR sem pedir confirmação; senão, pergunte antes do push. O PR segue `agentic/processo/templates/pr.md`, com as Rulings em "Decisões do orquestrador"; ao publicar, liste as Rulings ao humano e aponte as que pedem confirmação. Nunca faça merge.
6. Depois que o humano integrar (Gate 2), rode `git worktree remove agentic/.estado/worktrees/<nome>` e `git branch -d <branch>` (só `-d`, nunca `-D`). Não edite o Status: `integrada` deriva do git. Se o `-d` recusar, atualize antes a principal local; nunca use `-D`.
